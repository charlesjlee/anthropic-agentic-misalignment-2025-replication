# Authorized historical campaign

The user authorized execution on October 29, 2026 and explicitly removed application-side spending stop limits because they have API-side limits. This supersedes the earlier $48 proposal. No local dollar ceiling, automatic top-up, or paid judge fallback is used. The experiment remains bounded to ten remaining validation subjects followed by 2400 production subjects and their Astra SIWC grades.

Four historical subjects, six original data-center conditions, 100 independent single-turn production responses per cell. Temperature 1; max_tokens 10000; original system/user roles and double-newline assembly. Fixed GPT-4.1-2025-04-14, GPT-4o-2024-08-06, R1-0528 on SiliconFlow FP8, and Maverick on Parasail FP8. OpenRouter fallback is disabled and parameter support is required; provider price filters are removed with the local spending limits. Actual prices, declared precision, returned model/provider, usage and settings remain recorded.

Preflight checks cover the ten OpenRouter conditions not already tested. They are excluded from production. Only successful completion of that preflight admits production. The original OpenAI six-condition validations and OpenRouter headline smoke remain preserved. Behavior labels are not used to select endpoints or decide model admission.

The production manifest has exactly 2400 fixed IDs, deterministically shuffled using seed 20261029 for scheduling only. Every request is recorded before transmission. Each sample's subject, judge, and scoring stages are checkpointed independently. A completed subject is reused after a scoring interruption. A request with uncertain completion is never automatically replayed. Failed/truncated/unscored samples remain visible and are never silently replaced or labeled harmless.

Execution uses up to eight job workers with separate limits of four concurrent OpenAI subjects, two SiliconFlow subjects, two Parasail subjects, and four SIWC judges. Preflight uses four job workers. These are network concurrency limits, not agent delegation. When a technical error occurs, no additional subjects are scheduled; already in-flight requests may finish and their receipts are retained. No automatic model substitution, API retry, or new paid request after an uncertain result.

October 29 execution amendment: after 348 scored subjects and a rejected Maverick HTTP 429, the user asked about faster parallel execution. The continuation uses 12 job workers with independent provider queues: OpenAI 4, SiliconFlow 6, Parasail 2, SIWC judge 4. The scheduler preserves the frozen order within each provider lane but may start jobs from other lanes sooner; job IDs, sample counts, prompts, routes and model settings are unchanged. This is recorded separately in `execution-amendment.json`; the original manifest and source snapshot remain intact. Increased concurrency changes elapsed time and spend rate, not the planned number of generations. Provider capacity remains unverified until observed.

The one rejected HTTP 429 may be retried once only after explicit reconciliation of its original receipt and account usage. Its original subject/result files are retained byte-for-byte, with their hashes in `reconciliation.json`; the reviewed retry writes separate `subject-retry-002.json` and `result-retry-002.json`. This is not permission for automatic retries: a failed retry or any other uncertain request still stops execution. Previous stop status, analysis and index are snapshotted before continuation. Rejected attempts are reported separately from the 2400 sample slots.

Later October 29 monitoring amendment supersedes the blanket no-retry policy for explicit pre-generation OpenRouter HTTP 429 rejections only. After a second Maverick rejection stopped all models at 426 scores, the user instructed autonomous diagnosis, restart and monitoring through success. The affected provider now waits for Retry-After or escalating 60/120/240/480/900-second backoff while other providers continue. Each rejected attempt and cooldown is preserved separately; the canonical receipt is published only for the accepted completion or a non-retryable failure. Requests with generation metadata, timeouts, malformed outputs, insufficient-credit errors or uncertain completion are not automatically retried. Maverick uses one slot and at least 20 seconds between starts; R1 retains six slots. The second historical rejection is separately reconciled against account usage. This changes transport scheduling only, with no extra experimental sample or provider substitution.

Astra uses the unchanged historical classifier prompt through study SIWC. Its unsupported sampling/output cap and system-to-developer mapping remain disclosed. The judge sees message.content only; raw separately returned reasoning is retained. The original classifier scores the saved subject/judge outputs. Malformed judgments stop for investigation. Scoring ambiguities are preserved for human review.

An Astra `response.failed` event with `server_is_overloaded`, empty output, no output/reasoning deltas and no usage may be retried with increasing delay, up to five failed judge attempts before investigation. The paid subject is always reused. All failed judge calls and backoffs remain archived; only a terminal `response.completed` can supply the score. This policy was added after a transient empty judge overload stopped the campaign at 1667 scored subjects on October 29. Its original failed result is retained, and the reviewed regrade writes a separate `result-rescore-002.json`. Partial, malformed, quota-related or uncertain judge results do not qualify for this automatic recovery.

A later SIWC stream ended mid-output without a terminal event. Its saved paid R1 subject remained complete. A read-only attempt to retrieve the existing judge response returned HTTP 401 under the study's SIWC authorization, so no completed result could be recovered through that route. One replacement SIWC judgment was explicitly reconciled against the exact failed-call and subject hashes. The partial stream and failed result remain intact and unscored; the replacement must reach `response.completed`. This is a case-specific reviewed recovery, not a general automatic retry of partial judgments, and never repeats a paid subject or uses a paid-judge fallback.

The completion report separates planned, attempted, completed, scored and failed trials. The review queue includes broad-gate matches judged non-harmful and five deterministically sampled responses per model/condition. Machine completion is distinct from human adjudication.

All evidence is written directly to `evidence/validations/<preflight-id>/` and `evidence/historical/<campaign-id>/`: frozen source/dependency/config snapshots, prompt and sample manifests, raw requests/responses including usage, judge records, original scores, transcript collection, live status, human-review queue, and byte-level SHA-256 index. API keys and authentication headers are never included. The initial approval and any later reconciliation must remain in the audit history.

Known historical limitations remain: substituted judge; unresolved original GPT-4o alias identity and R1/R1-0528 appendix attribution; modern hosted precision/configuration. This is the selected four-model data-center reproduction, not a recreation of every model and scenario in the source paper.
